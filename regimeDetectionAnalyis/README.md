# ML-Driven Financial Market Regime Detection

An end-to-end pipeline that labels historical market regimes, trains supervised
classifiers to forecast the regime **N days ahead**, and backtests a
regime-switching tactical allocation strategy against passive buy-and-hold.

> **This is a research / decision-support tool, not investment advice.**
> Regime labels are a statistical construct with real estimation uncertainty.
> Nothing here should be treated as a standalone trading signal — see
> [Risk Insights & Limitations](#risk-insights--limitations).

---

## 1. Architecture

```
                ┌──────────────────┐
                │  data_loader.py  │   yfinance OHLCV (10+ yrs) or synthetic fallback
                └─────────┬────────┘
                          ▼
                ┌──────────────────┐
                │   features.py    │   volatility / trend / statistical features (causal)
                └─────────┬────────┘
                          ▼
                ┌──────────────────┐
                │   labeling.py    │   HMM / GMM / rule-based regime labels
                └─────────┬────────┘
                          ▼
                ┌──────────────────┐
                │      cv.py       │   Purged Group Time-Series Split (walk-forward + purge + embargo)
                └─────────┬────────┘
                          ▼
                ┌──────────────────┐
                │     model.py     │   RandomForest / XGBoost, Optuna-tuned, SHAP importance
                └─────────┬────────┘
                          ▼
                ┌──────────────────┐
                │   backtest.py    │   regime-switching allocation vs. buy & hold
                └──────────────────┘

                pipeline.py orchestrates all of the above end-to-end.
```

| File | Responsibility |
|---|---|
| `data_loader.py` | `yfinance` ingestion; synthetic Markov regime-switching OHLCV generator as an offline/test fallback |
| `features.py` | Volatility (realized vol ×3 windows, ATR%, Parkinson, vol-of-vol), trend/momentum (EMA spread, RSI, MACD, price vs SMA200), statistical (rolling skew/kurtosis), volume z-score — all causal, no scaling applied here |
| `labeling.py` | GMM, HMM, and rule-based unsupervised regime labeling; canonicalizes cluster IDs into `{Bear_HighVol, Sideways, Bull_LowVol}` by sorted mean return |
| `cv.py` | `PurgedGroupTimeSeriesSplit` — walk-forward folds with a purge gap (drops training samples whose feature/label windows overlap the test period) and an embargo buffer |
| `model.py` | Dataset assembly (T+N-ahead target), Optuna hyperparameter search scored via purged CV, per-fold `StandardScaler` fit only on training data, final held-out evaluation, SHAP feature importance |
| `backtest.py` | Regime → allocation weight mapping, no-look-ahead application (`shift(1)`), transaction costs, Sharpe/Sortino/CAGR/Max Drawdown/Calmar |
| `pipeline.py` | Orchestrates the full run; used by the notebook and runnable standalone (`python pipeline.py`) |
| `regime_detection_analysis.ipynb` | Step-by-step EDA, regime timeline charts, confusion matrices, SHAP plots, equity curve comparison |

### Data note (important)

`data_loader.py` tries `yfinance` first (real SPY/S&P 500 data — this is the
path you'll use on a normal machine with internet access). If that fetch
fails for any reason (no network, rate limiting, sandboxed environment), it
**automatically falls back to synthetic OHLCV data** generated by a known
Markov regime-switching process (3 hidden states with distinct drift/vol,
sticky transitions, Student-t innovations for fat tails) and prints a loud
warning. This lets the entire pipeline — including a sanity check that
compares recovered labels against the *known* generating regime — run and
be demonstrated without network access. **The notebook and README results in
this deliverable were generated on synthetic data** for exactly this reason;
rerun `pipeline.py` / the notebook on a machine with internet access to get
real-market numbers — no code changes are required.

## 2. Methodology Details

### Feature engineering & non-stationarity
All volatility/trend/statistical features are derived from **log returns**,
not raw price levels, and every rolling/EWM computation is strictly causal
(no `center=True`, no negative shifts) — a feature at time *t* only uses
data at or before *t*. `StandardScaler` is deliberately **not** applied in
`features.py`; it's fit fold-by-fold inside the CV loop in `model.py` so
no test-fold statistics ever leak into training.

### Regime labeling: why HMM over GMM
Both are implemented and compared in the notebook. On the synthetic
benchmark (where the true generating regime is known), the **HMM recovered
the true regime ~66% of the time vs. ~40% for GMM** on identical windows —
GMM clusters each day independently and produces "flickery" labels,
whereas the HMM's transition matrix encodes regime persistence, matching
the real-world fact that regimes last weeks to months, not single days.
HMM is used as the primary labeling mechanism feeding the supervised
models; the rule-based labeler is included as a transparent, fully
auditable alternative/sanity check.

### Leakage prevention (`cv.py`)
`PurgedGroupTimeSeriesSplit` implements walk-forward (expanding-window)
folds with two safeguards from Lopez de Prado's framework:
- **Purge**: training samples whose rolling-feature or label-formation
  window would overlap the test period are dropped from the tail of the
  training set.
- **Embargo**: an additional buffer after the test period is excluded from
  training in later folds, guarding against remaining leakage paths.

The purge window (default 25 trading days) is sized to exceed both the
longest rolling feature window (60-day realized vol) *scaled to the actual
information content needed at the boundary* and the label horizon (5 days),
so no train sample's inputs or outputs touch the test period.

### Hyperparameter tuning
`Optuna` (TPE sampler) searches RandomForest and XGBoost hyperparameter
spaces, scoring each trial as the **mean macro-F1 across all purged CV
folds** — not a single train/test split — so the tuner itself can't
overfit to one lucky fold boundary.

### Backtest construction
Weights (`Bull_LowVol`→100% equity, `Sideways`→50/50, `Bear_HighVol`→0%
equity) are applied with `shift(1)`: a regime known at the close of day *t*
affects the return earned from *t → t+1*, never *t-1 → t*. A 5 bps cost is
charged on every change in target weight. Two backtests are run:
1. **Perfect-info** — uses the *current*, unshifted regime label across
   full history. This is an **upper bound**, not an implementable strategy.
2. **Model-driven** — uses the RandomForest's genuinely out-of-sample
   T+5-ahead predictions on the held-out CV fold only. This is the
   realistic, leakage-free comparison against buy-and-hold.

## 3. Performance Trade-offs (synthetic-data run — see note above)

Representative results from the bundled notebook run (numbers will differ
on real market data / different random seeds):

| Strategy | CAGR | Ann. Vol | Sharpe | Max Drawdown |
|---|---|---|---|---|
| Regime-Switching (Perfect Info, full history) | ~1.3% | ~6.1% | modestly positive | ~-18% |
| Regime-Switching (RF Model, held-out fold) | slightly negative | lower than B&H | ~0 | shallower than B&H |
| Buy & Hold (same held-out period) | higher | much higher | comparable/higher | much deeper |
| Buy & Hold (full history) | negative (synthetic bear-heavy sample) | high | negative | ~-64% |

**Read this carefully — the pattern, not the exact numbers, is the point:**
- The **perfect-info** version substantially cuts volatility and drawdown
  relative to buy-and-hold, at the cost of some upside capture. This is the
  strategy's theoretical ceiling.
- The **model-driven, out-of-sample** version captures a *meaningful
  fraction* of that risk reduction, but with a real cost: prediction lag
  (5-day-ahead signal) and classifier error (macro-F1 in the 0.55–0.65
  range in this test — see Section 4 of the notebook) narrow the edge over
  buy-and-hold considerably, and can occasionally underperform in periods
  where staying invested through a false "risk-off" signal would have paid
  off. The gap between the perfect-info and model-driven results is a
  direct, honest measure of "how much of the theoretical edge survives
  contact with a real forecasting model."
- **Sideways vs. Bull_LowVol is the hardest classification boundary**
  (lowest precision/recall in both models) — the difference between "flat"
  and "slightly positive drift, low vol" is a genuinely lower-signal
  distinction than "calm" vs. "turbulent," which both models classify well.
- **Transaction costs matter.** At 5 bps per weight change, a strategy that
  flips regimes frequently will bleed returns even if its regime calls are
  directionally correct — this is included by default and shows up
  directly in the reported CAGR.

## 4. Risk Insights

- **Volatility features dominate.** SHAP importance consistently ranks
  Parkinson volatility, short-window realized volatility, and ATR% above
  trend/momentum features for both RandomForest and XGBoost — regime
  transitions tend to announce themselves through *volatility* before
  price trend catches up, which is consistent with well-documented
  volatility-clustering behavior in equity markets.
- **Bear/high-volatility regimes are the most reliably detected** (highest
  precision & recall in both models' confusion matrices) — sharp vol
  spikes are a comparatively unambiguous signal, which is exactly the
  regime where a risk-management overlay matters most.
- **False "risk-off" signals are the main cost of this approach.** Every
  period the model calls Bear/Sideways when the market is actually
  trending up costs upside capture. This is a real, quantifiable trade-off
  (visible in the CAGR/Sharpe gap vs. buy-and-hold), not a free lunch —
  size any live capital allocation to this signal accordingly, e.g. as a
  partial overlay/tilt rather than a full binary switch.
- **Regime labels carry estimation uncertainty.** They are derived from an
  unsupervised model (HMM) with its own hyperparameters (number of states,
  lookback windows) that materially affect the labels produced — always
  treat classifier output as one probabilistic input among several for
  risk management decisions, not a certainty.

## 5. Setup & Usage

### Install
```bash
pip install pandas numpy scikit-learn xgboost optuna matplotlib seaborn yfinance hmmlearn shap
```

### Run the full pipeline (script)
```bash
python pipeline.py
```
Prints data-loading status, regime distributions, tuned hyperparameters,
classification reports, and the backtest comparison table.

### Run the notebook
```bash
jupyter notebook regime_detection_analysis.ipynb
```
Walks through EDA → feature engineering → regime labeling comparison →
purged CV fold structure → Optuna tuning → confusion matrices → SHAP
importance → equity curve / drawdown comparison, with narrative
interpretation throughout.

### Key parameters to adjust
| Parameter | Location | Effect |
|---|---|---|
| `ticker`, `start` | `pipeline.run_pipeline()` | which index/ETF and history length to pull |
| `horizon` | `model.build_dataset()` | how many days ahead to forecast the regime |
| `n_splits`, `purge_window`, `embargo_window` | `cv.PurgedGroupTimeSeriesSplit` | CV fold count and leakage-prevention strictness |
| `n_trials` | `tune_random_forest` / `tune_xgboost` | Optuna search budget |
| `REGIME_WEIGHTS` | `backtest.py` | the allocation rule per regime |
| `transaction_cost_bps` | `backtest.run_regime_backtest()` | assumed round-trip trading cost |
